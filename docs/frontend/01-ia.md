> 阶段 1 产物（frontend-0to1-ai 步骤 1，角色 design/ux-researcher）。输入：`docs/frontend/00-brief.md`（commit `95cd9f3`）、`content/*.md`、`mock/*.json`。
> 线框：`design/wireframes/login.html`、`design/wireframes/dashboard.html`——纯灰度、无组件库、无图片、文案全部取 `content/` 的 key，数据全部取 `mock/`；同一文件用媒体查询覆盖 1440 与 375，`?state=` 切换状态（与 brief §4 的状态切换约定一致）。

## 1. 站点地图

```
/login                      无壳页（独立布局：品牌区 + 表单卡）
  ├─ 忘记密码？             不可达（aria-disabled）
  ├─ 免费注册 → /signup     不可达
  ├─ Google / GitHub / 微信 本轮仅视觉
  └─ 登录成功 → /?toast=login

/  仪表盘                    应用壳（侧边栏 + 顶栏）+ 概览内容
  ├─ 侧边栏 4 组 8 项（mock/nav.json）
  │   ├─ 概览：仪表盘 /                        ✔ 可达
  │   ├─ 交易：订单 /orders（角标 63）、售后 /after-sales（角标 7）   本轮 aria-disabled
  │   ├─ 货品：商品 /products、库存 /inventory（角标 12，warning）、采购 /purchasing   aria-disabled
  │   └─ 经营：报表 /reports、设置 /settings   aria-disabled
  ├─ 顶栏：面包屑「栖木家居 / 仪表盘」· 全局搜索 · 通知 Popover · 主题切换 · 头像菜单（5 项，退出登录 → /login）
  └─ 概览内容（success）：问候/更新时间 + 周期 Tabs → 4 统计卡 → 趋势图 + 环形图 → 最近订单 → 团队动态 ‖ 任务进度
      ├─ 查看全部（订单 / 动态）  不可达
      └─ 行内操作菜单：查看详情 / 标记发货 / 打印面单 / 取消订单（按状态禁用）
```

本轮只有 `/login` 与 `/` 两个真实路由；其余导航项与链接保留位置、渲染为 `aria-disabled` + Tooltip「后续轮次提供」（`shell.nav.disabled.tip`），不得 404（brief §4.2、§10-D）。

## 2. 每屏信息优先级（用户第一眼看什么）

### 2.1 login（/login）—「用工作邮箱进入团队空间」

| 序 | 元素 | 为什么在这个位置 | 文案 key（content/login.md） |
|---|---|---|---|
| ① | 邮箱 + 密码 + 主按钮「登录」 | 核心任务 1，每天 1 次；视线落点即表单卡顶部 | `title` `subtitle` `email.*` `password.*` `submit` |
| ② | 「30 天内记住我」复选 ‖ 「忘记密码？」链接 | 紧贴密码框，同一行左右分布：决策与补救并列 | `remember.label` `forgot.link` |
| ③ | 分隔线「或使用以下方式」+ 3 个等宽次级按钮 | 备选入口，弱于主按钮；文字标签 + CC0 单色图标位（线框用方框占位，不画商标） | `divider` `oauth.google/github/wechat` |
| ④ | 「还没有团队空间？免费注册」 | 表单卡底部，新用户出口 | `signup.prompt` `signup.link` |
| ⑤ | 品牌标 + 一句话价值 | 1440 在左栏承担"这是什么"的语境；375 只留品牌名，tagline 隐藏 | `brand.name` `brand.tagline` |
| ⑥ | 页脚：服务条款 · 隐私政策 · © 2026 Acme | 最弱层级 | `footer.*` |

反馈层级（自上而下压住表单）：顶部 Alert（`alert.invalid` / `alert.locked` / `alert.network`）> 字段内联错误（`error.*`）> 按钮 loading 文案（`submit.loading`）。

### 2.2 dashboard（/）—「打开即知今天生意如何、有什么要处理」

| 序 | 区块 | 第一眼要回答的问题 | 数据 / 文案 |
|---|---|---|---|
| ① | 4 张统计卡：销售额 ¥1,186,420（+9.4%）· 订单数 2,964 单（+5.1%）· 待发货 63 单（−21，中性）· 库存预警 12 SKU（+4，红为差） | 「今天生意如何」——数字 + 较上期方向 + 7 点迷你趋势 | `mock/stats.json`；`dashboard.delta.*` |
| ② | 问候「下午好，若琳」+ 「数据更新于 今天 17:30」+ 日 / 周 / 月 Tabs（默认 月） | 数字是哪个口径、是否新鲜；Tabs 同时驱动 ①③ | `dashboard.greeting` `dashboard.asOf` `dashboard.period.*` |
| ③ | 销售趋势（折线 = 销售额，柱 = 订单数，双 Y 轴）2/3 ‖ 渠道占比环形（5 渠道，中心合计）1/3 | 「趋势往哪走、钱从哪来」 | `mock/series.json` |
| ④ | 最近订单 5 行（订单号 / 客户 / 商品 / 金额 / 渠道 / 状态 / 下单时间 / 操作） | 「有什么要处理」——待发货 → 标记发货 / 打印面单；待付款 → 取消 | `mock/orders.json`；`dashboard.orders.*` |
| ⑤ | 团队动态时间线 6 条 ‖ 任务进度 5 条 | 「团队在做什么、哪件事有风险」 | `mock/activity.json` `mock/tasks.json` |
| ⑥ | 应用壳：侧边栏（含订单 63 / 售后 7 / 库存 12 角标）+ 顶栏（铃铛未读 3） | 常驻待办入口，弱于内容但角标可被余光捕捉 | `mock/nav.json` `mock/notifications.json`；`shell.*` |

375 下纵向顺序即 ②→①→③（趋势在上、环形在下）→④→⑤（动态在上、任务在下）（brief §4.2「顺序即 375 下的纵向顺序」）。

### 2.3 状态下的优先级变化

| 屏 / 态 | 变化 |
|---|---|
| login invalid | 两字段红边 + 内联错误置于字段下方（`aria-describedby`），主按钮仍可点 |
| login loading | 主按钮禁用 + spinner + 「登录中…」，全表单只读，第三方按钮同时禁用 |
| login error | 表单卡顶部 Alert 成为第一视觉层，聚焦到 Alert；字段值保留 |
| login success | 立即跳 `/?toast=login`：dashboard success 态右上角 Toast「欢迎回来，若琳」3 秒 |
| dashboard loading | 骨架屏，形状与 success 同布局（4 卡、2 图矩形、5 行、6 条、5 条），容器 `aria-busy`，无全屏 spinner |
| dashboard empty | 应用壳照常但团队空间名「未命名团队」、铃铛与侧边栏角标全部不显示；内容区只有居中空态（标题 / 说明 / 「接入销售渠道」/「导入历史订单」），问候改「你好，若琳」，不出现任何统计数字，周期 Tabs 不显示 |
| dashboard error | 应用壳照常；内容区居中错误块（标题 / 含 503 的说明 / 「重试」/ 辅助文字），重试 → loading → success |

## 3. 主流程（含错误 / 空态分支）

### 3.1 登录 → 仪表盘

```
/login (default)
  │ 输入邮箱、密码；可勾选「30 天内记住我」
  ├─ 字段失焦 / 提交，校验失败 ─────────▶ invalid：内联错误（请输入邮箱 / 邮箱格式不正确… / 请输入密码 / 密码至少 8 位）
  │                                          └─ 修正后再提交 ─┐
  ├─ 提交，校验通过 ────────────────────▶ loading：「登录中…」，表单只读 ◀┘
  │     ├─ 401 ──▶ error：alert.invalid（可关闭）──▶ 修改后重提交 ──▶ loading
  │     ├─ 423 ──▶ error：alert.locked ──▶ 只能走「忘记密码」（不可达）或等待
  │     ├─ 超时 ─▶ error：alert.network（warning，带「重试」）──▶ loading
  │     └─ 200 ──▶ success：跳 /?toast=login ──▶ dashboard success + Toast「欢迎回来，若琳」
  ├─ 「忘记密码？」/「免费注册」/ 第三方登录 ──▶ 本轮仅视觉，aria-disabled
  └─ 已勾选记住我且 30 天内 ──▶ 直接进 /（本轮不做持久化，仅说明）
```

演示账号规则（`mock/user.json.demoCredentials`）：`ruolin.shen@qimu-home.cn` + 任意 ≥8 位 → 200；`locked@qimu-home.cn` → 423；其它 → 401。

### 3.2 看概况 → 处理待办

```
/ (loading 骨架屏，aria-busy)
  ├─ 加载失败 ──▶ error：「数据加载失败」+ 503 说明 + 「重试」──▶ loading ──▶ success
  ├─ 新账号无数据 ──▶ empty：「还没有经营数据」+ 接入销售渠道 / 导入历史订单（不可达）
  └─ success
       ├─ 切 日 / 周 / 月 Tabs ──▶ 统计卡、趋势图、环形图同步切换（?period=）
       ├─ 统计卡「待发货 63」/ 侧边栏「订单 63」──▶ /orders 不可达（Tooltip「后续轮次提供」）
       ├─ 最近订单行 ▸ 更多操作
       │     ├─ 待发货：查看详情 / 标记发货 / 打印面单 / 取消订单
       │     ├─ 待付款：查看详情 / 取消订单（其余禁用）
       │     └─ 已发货 / 已完成 / 退款中：仅 查看详情
       ├─ 铃铛 ──▶ Popover：5 条通知（3 未读）/ 全部标为已读 / 查看全部通知（不可达）
       ├─ 主题切换 ──▶ 亮 / 暗（localStorage，?theme=）
       ├─ 头像 ──▶ 个人资料 / 账号安全 / 切换团队空间 / 帮助中心 / 退出登录 → /login
       └─ 375：汉堡 ──▶ 导航抽屉（同 8 项）；搜索缩为图标按钮
```

### 3.3 导航折叠

```
≥1440 展开（品牌 + 团队空间名 + 分组标题 + 图标 + 文案 + 角标）
  ⇄ 点「收起侧边栏」──▶ icon rail（只剩图形标 + 图标 + 角标点，文案进 Tooltip）
1024 默认折叠（icon rail）    ≤768 抽屉（顶栏汉堡「打开导航」打开，遮罩关闭）
```

## 4. 导航模型：应用壳 vs 无壳页

| | 无壳页（bare） | 应用壳页（shell） |
|---|---|---|
| 页面 | `/login`（后续：`/signup`、忘记密码） | `/`（后续：订单 / 售后 / 商品 / 库存 / 采购 / 报表 / 设置） |
| 1440 布局 | 左品牌区（品牌标 + tagline）+ 右表单卡（≤400px 居中于右栏），顶部无导航，底部页脚 | 左侧边栏 240 展开 / 64 折叠 + 右侧顶栏 56 + 内容区（最大宽 1280 居中，8pt 网格） |
| 375 布局 | 单列：品牌名 → 表单卡全宽（无卡边，直接贴页面）→ 页脚；tagline 隐藏；键盘弹起时主按钮仍在视口内（表单高度 ≤ 屏高 − 键盘） | 顶栏（汉堡 / 面包屑当前项「仪表盘」/ 搜索图标 / 铃铛 / 头像）+ 内容单列；侧边栏变抽屉；主题切换收进头像菜单上方的顶栏图标（保留） |
| 全局元素 | 无搜索 / 通知 / 主题切换（主题跟随系统或 `?theme=`） | 面包屑 · 搜索（⌘K）· 通知 · 主题 · 头像 |
| 状态承载 | Alert 在表单卡顶部；Toast 不在本页（成功即跳转） | Toast 右上角（375 顶部居中）；loading / empty / error 只替换内容区，壳不变 |
| 焦点起点 | 邮箱输入框 | 内容区 h1「仪表盘」（1440 视觉弱化但保留语义） |

## 5. 线框说明（design/wireframes/）

- `login.html`：`?state=default|invalid|loading|error`（`success` 与 brief 一致直接跳 `dashboard.html?toast=login`）。
- `dashboard.html`：`?state=success|loading|empty|error`、`?toast=login`；顶部标注栏含状态链接与 `?period=` 说明（线框中 Tabs 只标默认「月」，切换效果在实现阶段做；三个周期的数据口径见 `mock/README.md`）。
- 纯灰度：只用 `#000–#fff` 灰阶（线框内以 `--g0…--g100` 命名的灰阶变量表达层级，**不是**阶段 2 令牌，阶段 2 另建 `design/tokens.json`）；无图片、无图标集，图标一律用 24px 方框 + 名称占位（对应 `mock/nav.json.icon` 的 Lucide 名）。
- 所有数字、订单、人名来自 `mock/*.json`，所有文案来自 `content/*.md` 的 key；线框中的图表是用 `mock/series.json` 月度 30 点与渠道占比按比例绘制的 SVG，不是示意随机线。
- 1440 与 375 同一文件，`@media (max-width: 767px)` 切换到 375 布局，页面 `scrollWidth ≤ 375`。

## 6. 阶段 1 取舍（brief 标注「阶段 1 定」的项，如无异议按此执行）

| # | 议题 | 决定 | 理由 |
|---|---|---|---|
| A | login 1440 布局：左右分栏 vs 居中卡 | **左右分栏**：左 5/12 品牌区（品牌标 + tagline + 一行说明位，纯灰底），右 7/12 放 ≤400px 表单卡 | 「品牌标与一句话价值」是 brief 第 ⑤ 优先级，分栏能给它固定位置又不抢表单；375 收成单列时左栏自然消失 |
| B | 375 统计卡：单列 vs 2×2 | **2×2**（卡内：标签 → 主数字 → 较上期；迷你趋势缩为 1 行细线） | 手机场景 1–2 分钟「抬手看」，4 个数字必须在首屏同时可见；单列会把库存预警推到第二屏 |
| C | 375 最近订单：横向滚动 vs 卡片化 | **卡片化**：每单一张卡，行 1 = 订单号 + 状态 Tag，行 2 = 商品（多件「等 n 件」），行 3 = 金额（右对齐）· 渠道 · 时间，右上角「更多操作」按钮 ≥40px | 仓储主管 50% 用手机且需直接对待发货单操作，状态与操作必须不滑动即见；`dashboard.orders.mobileHint`「左右滑动查看更多」留给 768 表格横向滚动 |
| D | 375 图表顺序 | 趋势图在上、环形图在下，趋势图高度 200、环形 240（图 + 5 行图例） | 趋势回答「往哪走」优先于「钱从哪来」 |
| E | 375 h1 | 顶栏面包屑只显示当前项「仪表盘」，内容区不重复 h1（语义保留、视觉隐藏） | 顶栏已承担标题，避免同屏两次「仪表盘」 |
| F | empty 态 Tabs | 空态不显示周期 Tabs 与统计区块 | 无数据时切周期无意义；brief「不显示任何统计卡数字」 |
| G | 主题切换在 375 | 保留在顶栏图标区（汉堡 / 标题 / 搜索 / 铃铛 / 主题 / 头像），每个热区 40px，共 5 个图标按钮 | 老板原话明确要主题切换，且 40×5 = 200 < 375 可容纳 |
| H | 第三方登录按钮排布 | 1440 与 375 均为 3 行全宽按钮（图标 + 「使用 Google / GitHub / 微信继续」） | 400px 卡内 3 列每格约 110px，中文 + 品牌名会折成 3 行；全宽更稳且与主按钮对齐 |
