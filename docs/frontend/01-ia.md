### 2.3 状态下的优先级变化

| 屏 / 态 | 变化 |
|---|---|

| dashboard loading | 骨架屏，形状与 success 同布局（4 卡、2 图矩形、5 行、6 条、5 条），容器 `aria-busy`，无全屏 spinner |
| dashboard empty | 应用壳照常但团队空间名「未命名团队」、铃铛与侧边栏角标全部不显示；内容区只有居中空态（标题 / 说明 / 「接入销售渠道」/「导入历史订单」），问候改「你好，若琳」，不出现任何统计数字，周期 Tabs 不显示 |

## 3. 主流程（含错误 / 空态分支）

### 3.1 登录 → 仪表盘

```
/login (default)
  │ 输入邮箱、密码；可勾选「30 天内记住我」
  ├─ 字段失焦 / 提交，校验失败 ─────────▶ invalid：内联错误（请输入邮箱 / 邮箱格式不正确… / 请输入密码 / 密码至少 8 位）
  │                                          └─ 修正后再提交 ─┐
  ├─ 提交，校验通过 ────────────────────▶ loading：「登录中…」，表单只读 ◀┘
  │     ├─ 401 ──▶ error：alert.invalid（可关闭）──▶ 修改后重提交 ──▶ loading
  │     ├─ 423 ──▶ error：alert.locked ──▶ 只能走「忘记密码」（不可达）或等待
  │     ├─ 超时 ─▶ error：alert.network（warning，带「重试」）──▶ loading
  │     └─ 200 ──▶ success：跳 /?toast=login ──▶ dashboard success + Toast「欢迎回来，若琳」
  ├─ 「忘记密码？」/「免费注册」/ 第三方登录 ──▶ 本轮仅视觉，aria-disabled
  └─ 已勾选记住我且 30 天内 ──▶ 直接进 /（本轮不做持久化，仅说明）
```

演示账号规则（`mock/user.json.demoCredentials`）：`ruolin.shen@qimu-home.cn` + 任意 ≥8 位 → 200；`locked@qimu-home.cn` → 423；其它 → 401。

### 3.2 看概况 → 处理待办

```
/ (loading 骨架屏，aria-busy)
  ├─ 加载失败 ──▶ error：「数据加载失败」+ 503 说明 + 「重试」──▶ loading ──▶ success
  ├─ 新账号无数据 ──▶ empty：「还没有经营数据」+ 接入销售渠道 / 导入历史订单（不可达）
  └─ success
       ├─ 切 日 / 周 / 月 Tabs ──▶ 统计卡、趋势图、环形图同步切换（?period=）
       ├─ 统计卡「待发货 63」/ 侧边栏「订单 63」──▶ /orders 不可达（Tooltip「后续轮次提供」）
       ├─ 最近订单行 ▸ 更多操作
       │     ├─ 待发货：查看详情 / 标记发货 / 打印面单 / 取消订单
       │     ├─ 待付款：查看详情 / 取消订单（其余禁用）
       │     └─ 已发货 / 已完成 / 退款中：仅 查看详情
       ├─ 铃铛 ──▶ Popover：5 条通知（3 未读）/ 全部标为已读 / 查看全部通知（不可达）
       ├─ 主题切换 ──▶ 亮 / 暗（localStorage，?theme=）
       ├─ 头像 ──▶ 个人资料 / 账号安全 / 切换团队空间 / 帮助中心 / 退出登录 → /login
       └─ 375：汉堡 ──▶ 导航抽屉（同 8 项）；搜索缩为图标按钮
```

## 5. 线框说明（design/wireframes/）

- `login.html`：`?state=default|invalid|loading|error`（`success` 与 brief 一致直接跳 `dashboard.html?toast=login`）。
- `dashboard.html`：`?state=success|loading|empty|error`、`?toast=login`；顶部标注栏含状态链接与 `?period=` 说明（线框中 Tabs 只标默认「月」，切换效果在实现阶段做；三个周期的数据口径见 `mock/README.md`）。
- 纯灰度：只用 `#000–#fff` 灰阶（线框内以 `--g0…--g100` 命名的灰阶变量表达层级，**不是**阶段 2 令牌，阶段 2 另建 `design/tokens.json`）；无图片、无图标集，图标一律用 24px 方框 + 名称占位（对应 `mock/nav.json.icon` 的 Lucide 名）。
- 所有数字、订单、人名来自 `mock/*.json`，所有文案来自 `content/*.md` 的 key；线框中的图表是用 `mock/series.json` 月度 30 点与渠道占比按比例绘制的 SVG，不是示意随机线。
- 1440 与 375 同一文件，`@media (max-width: 767px)` 切换到 375 布局，页面 `scrollWidth ≤ 375`。

## 6. 阶段 1 取舍（brief 标注「阶段 1 定」的项，如无异议按此执行）

| # | 议题 | 决定 | 理由 |
|---|---|---|---|
| A | login 1440 布局：左右分栏 vs 居中卡 | **左右分栏**：左 5/12 品牌区（品牌标 + tagline + 一行说明位，纯灰底），右 7/12 放 ≤400px 表单卡 | 「品牌标与一句话价值」是 brief 第 ⑤ 优先级，分栏能给它固定位置又不抢表单；375 收成单列时左栏自然消失 |
| B | 375 统计卡：单列 vs 2×2 | **2×2**（卡内：标签 → 主数字 → 较上期；迷你趋势缩为 1 行细线） | 手机场景 1–2 分钟「抬手看」，4 个数字必须在首屏同时可见；单列会把库存预警推到第二屏 |
| C | 375 最近订单：横向滚动 vs 卡片化 | **卡片化**：每单一张卡，行 1 = 订单号 + 状态 Tag，行 2 = 商品（多件「等 n 件」），行 3 = 金额（右对齐）· 渠道 · 时间，右上角「更多操作」按钮 ≥40px | 仓储主管 50% 用手机且需直接对待发货单操作，状态与操作必须不滑动即见；`dashboard.orders.mobileHint`「左右滑动查看更多」留给 768 表格横向滚动 |
| D | 375 图表顺序 | 趋势图在上、环形图在下，趋势图高度 200、环形 240（图 + 5 行图例） | 趋势回答「往哪走」优先于「钱从哪来」 |
| E | 375 h1 | 顶栏面包屑只显示当前项「仪表盘」，内容区不重复 h1（语义保留、视觉隐藏） | 顶栏已承担标题，避免同屏两次「仪表盘」 |
| F | empty 态 Tabs | 空态不显示周期 Tabs 与统计区块 | 无数据时切周期无意义；brief「不显示任何统计卡数字」 |
| G | 主题切换在 375 | 保留在顶栏图标区（汉堡 / 标题 / 搜索 / 铃铛 / 主题 / 头像），每个热区 40px，共 5 个图标按钮 | 老板原话明确要主题切换，且 40×5 = 200 < 375 可容纳 |
| H | 第三方登录按钮排布 | 1440 与 375 均为 3 行全宽按钮（图标 + 「使用 Google / GitHub / 微信继续」） | 400px 卡内 3 列每格约 110px，中文 + 品牌名会折成 3 行；全宽更稳且与主按钮对齐 |
